# Violetta Apply Assistant · 3.9.9


## 3.9.9 — постоянная память вакансий и продолжение форм

- Состояние карточки теперь хранится по **точному `vacancyId`**, а не только в DOM текущей страницы. После перехода на анкету, возврата назад, обновления выдачи или повторного появления той же вакансии восстанавливаются `Analysis`, статус отклика и прогресс формы.
- Перед переходом с карточки в анкету сохраняется точный application context. На HH-форме расширение продолжает именно этот отклик в той же вкладке и не перепривязывает его к соседней вакансии.
- Подтверждённые данные кандидата, сопроводительное письмо и подходящий встроенный CV заполняются автоматически, когда поле однозначно распознано.
- Зарплата, юридические согласия, право на работу, дата выхода, неподтверждённый стаж и другие неизвестные/рисковые ответы **не выдумываются**: они остаются отмеченными для ручной проверки.
- Финальная кнопка отправки анкеты не нажимается автоматически в продолженном form-flow. После автозаполнения пользователь проверяет оставшиеся поля и подтверждает отправку сам.
- Если эта же вакансия снова появляется в выдаче, сохранённый результат `Analysis` и application/form state восстанавливаются без повторного анализа.

## 3.9.8 — авто-закрытие уже просмотренного отклика

Если HH открывает окно «Сопроводительное письмо», но после попытки отправки сообщает **«Отклик уже просмотрен работодателем»**, расширение теперь распознаёт именно этот терминальный статус, автоматически нажимает **«Закрыть»**, не показывает ложную ошибку/повтор и возвращает пользователя к списку вакансий. Карточка получает состояние **`✓ Уже просмотрен`**. Другие ошибки отправки не закрываются автоматически.

## 3.9.7 — Analysis читает саму вакансию в фоне

На каждой карточке HH рядом с `✦ Отклик + письмо` есть **`Analysis`**. После нажатия расширение берёт точный `vacancy ID`, открывает именно эту вакансию в **неактивной фоновой вкладке**, читает полное описание, проверяет ID и сразу закрывает техническую вкладку. Текущая страница поиска не переключается.

Результат:

- **`✓ Без звонков`** — в полном описании нет обязанности звонить или прямо указаны чат/переписка/без звонков;
- **`✕ Есть звонки`** — найдены входящие/исходящие или другие рабочие звонки, телефонная/голосовая поддержка, call-center и аналогичные обязанности;
- **`↻ Повторить`** — полную вакансию не удалось прочитать ни через фоновую страницу, ни через HH API. В этом случае расширение не угадывает.

Важно: техническая фраза вроде `настраивать телефонию / SIP / VoIP` сама по себе **не означает**, что нужно принимать звонки. `Analysis` ничего не отправляет; после зелёного результата можно отдельно нажать `✦ Отклик + письмо`.


## 3.9.7 — точный быстрый отклик из списка + постоянные ✦ Apply / ✎ AI на HH

- На прямой странице `hh.ru/vacancy/<id>` поисковые/фильтровые формы больше не ошибочно считаются формой отклика, поэтому `✦ Apply` не скрывается.
- Service worker повторно подключает интерфейс при активации вкладки и SPA-навигации HH, без необходимости открывать popup расширения.
- После одного явного разрешения Chrome доступ запрашивается сразу для `hh.ru` и всех `*.hh.ru`, а не по одному региональному поддомену.
- `✦ Apply` умеет продолжить шаг «Приложить письмо», если резюме на HH уже отправлено, а письмо ещё не подтверждено.
- GitHub Actions обновлены под текущий `browser-extension/`, чтобы старые проверки UI 2.x/3.0 не ломали CI 3.9.x.

> Chrome не позволяет расширению самостоятельно отменить пользовательский режим **«Доступ только при нажатии»**. Если он был выставлен вручную, нужно один раз разрешить доступ к HH.ru / HeadHunter.kg; после этого 3.9.7 поддерживает интерфейс автоматически.

**Extension-first режим:** после загрузки папки `extension` в Chrome основные функции работают без обязательного запуска `start-assistant.cmd`.

## Что работает без терминала

| Действие | Автономный режим |
|---|---|
| ✦ Apply | Да — кнопка появляется на поддерживаемой вакансии и запускает локальную подготовку/отклик через extension service worker. |
| ✎ AI | Да — ручка появляется в активном recruiter chat, читает доступный DOM и использует память кандидата. |
| HH quick apply | Да — после вашего клика `Откликнуться` расширение может подготовить vacancy-specific письмо. |
| Candidate Truth Memory | Да — CV/HH/current Technical Support + freelance facts хранятся в расширении. |
| RU/EN CV | Да — встроенные PDF доступны расширению. |
| Внешняя AI-модель | Опционально — настраивается прямо в extension settings. |
| 🚀 Автопилот очереди/дашборда | Расширенный режим — использует локальный backend. |

### 3.9.7 vacancy-card isolation

На странице поиска письмо всегда связывается с выбранной карточкой/vacancy ID. Заголовки страницы поиска (`Найдено N вакансий`) не используются как название вакансии. Если полная карточка не может быть подтверждена, отправка останавливается вместо общего письма.

## 3.9.7 — устойчивые кнопки на странице

- На прямой HH-вакансии `/vacancy/<id>` кнопка **✦ Apply** больше не зависит от готовности backend.
- На HH-переписке **✎ AI** остаётся видимой даже при SPA-переходах и старых чатах, если доступен composer.
- После `Load unpacked` service worker проверяет уже открытые HH-вкладки и при необходимости переинжектит UI.
- Добавлен watchdog для SPA-переходов, чтобы кнопки возвращались после смены вакансии/чата без полной перезагрузки.
- Backend readiness больше не блокирует core readiness: без backend доступны Apply/Fill/Chat AI; backend отмечается как optional advanced service.

## Память и письма

Версия 3.9.7 сохраняет evidence-first стратегию 3.8:

**полная вакансия → релевантные подтверждённые факты → короткое человеческое письмо.**

Для технических ролей используются только релевантные подтверждённые обязанности и проекты: текущий Technical Support / Integration Support опыт, freelance development, API/SQL/.NET и подходящие проекты. **Названия прежних работодателей и учебного заведения в сопроводительное письмо не вставляются**; при необходимости указывается сама роль, задачи и профильное образование в области информационных систем и программирования. Нерелевантная hospitality-история не подставляется в developer/QA письма. GitHub добавляется только в техническом контексте.

**Нет гарантии прохождения ATS или “невидимости” для AI-detectors.** Цель — правдивый, короткий и контекстный текст.

## ✎ AI в чате

`✎ AI → Проанализировать весь диалог и ответить`

Ассистент:
- читает активную переписку;
- определяет последнее сообщение работодателя;
- использует Candidate Truth Profile;
- учитывает vacancy / CV / Cover Letter Memory, если связь известна;
- создаёт черновик;
- **не нажимает Send**.

Локальный режим отвечает только там, где хватает подтверждённых фактов. Для свободного редактирования и сложных вопросов можно подключить совместимую Chat Completions модель в `Настройки → AI и ответы`.

## Быстрый запуск

1. Распакуйте ZIP.
2. Chrome → `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное**.
5. Выберите папку `extension`.

После этого базовые **✦ Apply** и **✎ AI** должны работать без отдельного терминала.

Если вкладка HH была открыта до загрузки расширения, 3.9.7 пытается подключиться автоматически; при ограничениях Chrome достаточно один раз обновить вкладку.

## Расширенный backend

- серверной очереди/аналитики.
